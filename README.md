# Public Intel CPU compiler checkpoints - enabling candidate

Local enabling preparation only: no upload, ref update or launch is performed by preparation. The previous cold Intel run44551973432 ended at its150-minute Torch phase cap with no wheel; its CPU configuration passed, but actual compile progress was not captured. The new profile gives more time and checkpoints completed compiler objects; the first attempt remains cold because that earlier job had no ccache. No successful retry, paid use or storage-setting change is implied.

The candidate retains exactly seven generic public recipe files. It accepts no application checkout, private source, model/checkpoint bytes, activation material, customer data or private endpoint. The only new dependency is a temporary, SHA-pinned ccache4.14.3 build tool. All Python3.11.18, NumPy2.2.6, PyTorch2.13.0, TorchVision0.28.0, CMake4.1.2, Ninja1.13.0 and other library/source pins remain unchanged.

## Compiler cache only

The public ccache4.14.3 archive is bound to SHA-256 `764dd2a8100ff83e6bbd7b9a1e2016cc401be34bee8a70ea99698186622c34d5`. Only its expected executable member is extracted after archive verification; it is not included in artifacts. The cache key binds actual compiler bytes/version, Xcode, SDK, ccache version and the complete public lock. Normal GitHub branch/default-branch scope applies. A miss is honestly a cold build.

All four C/CXX/OBJC/OBJCXX CMake compiler-launcher variables and the explicit ccache config/live/temp paths are retained in the filtered third-party build environment. The verified tool directory is prepended to the filtered PATH because the pinned Torch CMake auto-finds ccache; actual main C/CXX launcher entries must match the pinned executable. OBJC/OBJCXX are checked when their compiler or launcher is present; disabled-language entries may be absent and are reported as null. CI repository/runtime tokens and unrelated secret environment variables are excluded. No model, HOME, pip download cache, source/build tree, executable release or credential directory is saved. Direct mode, hard links, file clones, relaxed sloppiness and remote storage are disabled; source/compiler/options checking remains ccache's responsibility.

The live cleanup target is1800MiB. A separate closed snapshot is capped at2GiB including its SHA manifest and30000 completed cache entries. Only the pinned ccache40-hex layout is accepted; lock/temp/stats/config files are excluded. Directory visits and copy/verify time are bounded. Each regular non-hard-linked input is copied through a separate descriptor, with inode/size/time/mode checks before and after; replaced or growing entries are skipped. Symlinks, special files, unsafe paths, hash mismatches and overflow fail closed. The snapshot is reverified after closing and the cache action reads only that copy. Compiler descendants cannot keep a descriptor to the copied snapshot.

Restore verifies the exact manifest, compiler key and every listed byte before copying to a fresh writable cache; the received snapshot is retained under a separate consumed name without deletion. Completed objects are checkpointed after controller success or failure. Hard runner cancellation can prevent saving; direct-parent timeouts do not guarantee descendant cleanup. A cache is a build acceleration artifact, not a successful wheel or release.

## Free-storage admission

Public standard compute is free; artifact and cache storage are separate allowances. Immediately before cache save, the isolated admission mode uses the normal same-repository CI read token only for documented `GET https://api.github.com/repos/{owner}/{repo}/actions/cache/usage`. It verifies the event and response identify the same public repository, refuses redirects, bounds the JSON response and records only safe usage data or an exception type. The token is never logged, put in a command line, saved in evidence or forwarded to public source/build/probe subprocesses.

Admission requires actual repository used bytes plus the full2GiB new-snapshot reserve plus128MiB archive/concurrency margin to be at most a conservative10,000,000,000-byte free ceiling. Missing/invalid/unavailable usage disables cache saving. Root must also establish that no competing cache writer outside this serialized Intel recipe can race the readback; a usage response is not a billing lock. No cache-size limit, payment setting or billing budget is changed, and unrelated caches are never deleted. Increasing the repository limit or paid cache storage is not authorized by this recipe.

GitHub documents cache-usage data as refreshed approximately every five minutes and says updates may take at least five minutes. Before publishing or running this profile, root must establish the sole-writer condition and that earlier cache saves have been quiet for more than five minutes. This is not an instantaneous usage or billing lock; if freshness or the writer boundary cannot be established, cache saving must remain disabled.

The artifact policy is unchanged: a closed text-evidence snapshot capped at20MiB for one day. Optional wheels, original license notices, checksums and evidence share a256MiB aggregate cap, and wheels are shared only after both wheel inspections and the final CPU ABI probe pass. Failed/partial builds share text evidence only. Exceeding the cap uploads nothing. Compiler-cache entries are not uploaded as wheel/evidence artifacts.

## Empty-default config correction and pre-clone compiler check

The first cache-enabled native attempt failed inside CMake try-compile with `ccache: error: URL scheme must not be empty: sloppiness`. In pinned ccache4.14.3, the config reader can advance past the newline of an explicitly empty assignment. This recipe therefore omits `remote_storage` and `sloppiness`; both pinned upstream defaults are empty. No tool/source/version or CPU component is changed.

Before cloning upstream source, the closed-restore step invokes the actual pinned executable with `--get-config remote_storage` and `--get-config sloppiness` in the existing filtered child environment. Both effective values must be empty. Raw configuration values are never printed, and inherited CCACHE remote/sloppiness overrides and CI tokens are not forwarded. The same filtered environment must compile a tiny C++ object through the pinned ccache wrapper and produce a nonempty native Intel object. Its bounded compiler log and receipt describe only this build-tool check, not PyTorch or application compatibility.

Primary source: [pinned config defaults](https://github.com/ccache/ccache/blob/v4.14.3/src/ccache/config.hpp), [pinned config reader](https://github.com/ccache/ccache/blob/v4.14.3/src/ccache/util/configreader.cpp).
